## Findings and recommendations

### W6-01 — P1: download delivery precedes successful debit

**Evidence:** [star-map-app-final/src/components/EditorExperience.tsx:1618–1629](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/components/EditorExperience.tsx#L1618-L1629) renders and triggers the HD blob before awaiting consume. [star-map-app-final/src/lib/hdExportFulfillment.ts:13–28](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/hdExportFulfillment.ts#L13-L28) clicks a blob URL locally; [star-map-app-final/src/lib/hdExportFulfillment.ts:55–77](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/hdExportFulfillment.ts#L55-L77) can subsequently report consume failure. Per-component refs suppress overlapping local calls ([star-map-app-final/src/components/EditorExperience.tsx:880–902](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/components/EditorExperience.tsx#L880-L902) and [star-map-app-final/src/components/EditorExperience.tsx:1584–1591](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/components/EditorExperience.tsx#L1584-L1591)), not another device/tab.

**Impact / conditional schedule:** two eligible browser contexts can start separate exports before either debit settles. Even if the server correctly refuses the second debit for no credits, bytes have already been handed to that browser. Blocking/failing the consume request similarly leaves a delivered file without confirmed accounting. This is a delivery/accounting boundary gap, not proof that DO commits themselves can overdraw. No live bypass attempted.

**Recommendation only:** complete the owner-controlled server-authorized artifact/commit/delivery path. Bind each debit to finalized artifact identity, record ownership atomically, and release the authorized file after commit. Exercise two devices with one allowance, consume failure after render, and retry of the same owned artifact. Do not merely move a browser fetch ahead of an otherwise client-controlled renderer and call that a complete authority boundary.

### W6-02 — P1: legacy download and claim readers omit terminal side evidence

**Evidence:** archive authorization reads only claim, session digital-access fields and governing token ([star-map-app-final/src/app/api/download/archive/route.ts:60–102](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/app/api/download/archive/route.ts#L60-L102)); helper rejects only the record's revoked flag ([star-map-app-final/src/lib/accountAccessEntitlements.mjs:19–26](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/accountAccessEntitlements.mjs#L19-L26)). Claim route likewise checks the session flag ([star-map-app-final/src/app/api/entitlements/claim/route.ts:19–48](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/app/api/entitlements/claim/route.ts#L19-L48)). Separate session/PI evidence is read by [star-map-app-final/src/lib/entitlementsStore.ts:377–425](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/entitlementsStore.ts#L377-L425) and written by revocation ([star-map-app-final/src/app/api/stripe/webhook/route.ts:703–740](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/app/api/stripe/webhook/route.ts#L703-L740)). Settlement's later whole-session put and post-check explicitly leave a revocation overlap ([star-map-app-final/src/lib/entitlementsStore.ts:906–932](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/entitlementsStore.ts#L906-L932)).

**Impact / precondition:** if a stale active session image is visible or republished after revocation while its claim remains valid, these readers can authorize despite preserved terminal evidence elsewhere. A successful refund does not imply every download reader enforces that evidence. Token rotation checks are a useful separate control, not a refund check. No incidence or propagation duration measured.

**Recommendation only:** make every serving/access-cookie boundary consult a common error-preserving terminal authority, failing closed when unreadable. Test active session + revoked sidecar, PI tombstone, stale replacement after refund, and archive read concurrent with revocation. Coordinate with DL-1 owner rather than patching readers here.

### W6-03 — P1: initial settlement remains a non-atomic balance reconstruction path

**Evidence:** [star-map-app-final/src/lib/entitlementsStore.ts:701–751](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/entitlementsStore.ts#L701-L751) checks an ordinary KV read before deciding whether a purchase is already settled. Initialization writes intent and then a full initial record ([star-map-app-final/src/lib/entitlementsStore.ts:879–935](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/entitlementsStore.ts#L879-L935)); verify's builder restores the purchased allowance ([star-map-app-final/src/app/api/stripe/verify/route.ts:397–408](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/app/api/stripe/verify/route.ts#L397-L408)). KV adapter uses unconditional put ([star-map-app-final/src/lib/kv.ts:278–301](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/kv.ts#L278-L301)). The code explicitly retains stale-absence and refund/put races ([star-map-app-final/src/lib/entitlementsStore.ts:183–189](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/entitlementsStore.ts#L183-L189)).

**Impact / conditional schedule:** a replay reading stale absence can initialize full purchased credits after prior consumption, or publish active state over a concurrent revocation. Visible-replay suppression and durable intent reduce risk but do not serialize this check-and-write. The legacy consume lease cannot be assumed to protect a settlement writer that does not acquire it. This is a known retained architectural residual, not a newly proven production exploit.

**Recommendation only:** serialize own-purchase grants and terminal revocations under the same durable authority using stable purchase operation IDs; retain distinct pending/ambiguous outcomes. Test stale absence after debit, simultaneous verify/webhook initialization, and refund between final check and put. Do not use KV lock keys as a substitute for conditional durable transitions.

### W6-04 — P2: legacy idempotency remembers only the most recent consume

**Evidence:** [star-map-app-final/src/lib/entitlementConsume.mjs:35–58](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/entitlementConsume.mjs#L35-L58) deduplicates only lastConsumeToken and replaces it on the next debit. Route passes the request token directly ([star-map-app-final/src/app/api/entitlements/consume/route.ts:33–40](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/app/api/entitlements/consume/route.ts#L33-L40)). In contrast DO commit deduplicates by owned artifact ([star-map-app-final/src/lib/entitlementAuthorityState.ts:2177–2186](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/entitlementAuthorityState.ts#L2177-L2186)).

**Impact:** on a finite balance with at least three credits, A → B → retry A debits three times. Lease serialization does not supply persistent operation history. This can overcharge retries from an API caller preserving A across another operation; the standard UI normally generates new tokens ([star-map-app-final/src/components/EditorExperience.tsx:880–886](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/components/EditorExperience.tsx#L880-L886)), so automatic UI occurrence is not asserted.

**Recommendation only:** bind durable idempotency to artifact/operation identity, retaining prior outcomes across intervening requests. Test A/B/A, simultaneous same-token calls, and compensation followed by retry. Route remediation belongs to the DL-1 owner.

### W6-05 — P1: KV loss destroys legacy accounting evidence; payment replay is unsafe recovery

**Evidence:** legacy consumed balance and last-operation evidence live in the mutable session ([star-map-app-final/src/lib/entitlementConsume.mjs:46–59](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/entitlementConsume.mjs#L46-L59)); settlement intents/adoption/revocation/claim keys are also KV ([star-map-app-final/src/lib/entitlementsStore.ts:68–100](https://github.com/daveybehavey/starMapAppV2/blob/b12585834e4952fd3bebd7444b7adbb158088461/star-map-app-final/src/lib/entitlementsStore.ts#L68-L100)). **Impact:** total KV loss removes the legacy remaining-balance history, token associations and revocation sidecars together. Keep recovery records outside the failing namespace and demonstrate a restore drill with grants, debits, compensation and refund cases. Open #582 owns KV exporter/notes; do not duplicate or edit that work. A KV export alone does not back up DO state or R2.
